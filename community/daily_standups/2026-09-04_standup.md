8. The "absence vs zero" principle should become a Myavana engineering rule

This is probably the most valuable discovery in that entire standup.

You have multiple manifestations of the same underlying failure:

missing profile
      ↓
fictional profile

missing health score
      ↓
0

missing routine
      ↓
0% completion

missing hair measurement
      ↓
0

API envelope misunderstood
      ↓
undefined values presented as valid state

That's not five unrelated bugs.

It's one product/data integrity problem.

I'd formally name it:

No Silent Fabrication / Absence Must Remain Absent

The rule:

UNKNOWN ≠ ZERO
UNKNOWN ≠ EMPTY SUCCESS
UNKNOWN ≠ DEFAULT USER
UNKNOWN ≠ PLAUSIBLE DATA

For Myavana especially, this is critical because incorrect hair data can subsequently affect Mya's recommendations.

Directive

Adopt "absence must remain absent" as a cross-repo engineering rule. Any unavailable, missing, unauthorized, or unconfigured data must render as an explicit unavailable/empty state rather than a plausible default. Audit new integrations for this pattern.

I'd put that in the main engineering/collaboration documentation.
